## Precedence

Lowest to highest:

1. Built-in defaults
2. `/etc/kuben/config.toml`
3. `./kuben.toml` (the nearest one: the working directory, else its parents)
4. `--config <file>` or `KUBEN_CONFIG` (if given)
5. `KUBEN_*` environment variables. Nested keys are separated by `__`: `KUBEN_SECURITY__SESSION_TTL_HOURS`. A value may be written as in TOML: a list `[a, b]`, a table `{admins = "admin"}`, `true`, a number; anything else is a string.

Keys Kuben does not read are ignored; a value of the wrong type stops the server at start.

A TOML file uses the same sections:

```toml title="kuben.toml"
[server]
bind = "127.0.0.1:8080"
public_url = "https://kuben.example.com"

[database]
url = "postgres:///kuben?host=/run/postgresql&user=kuben"

[security]
trust_forwarded_for = true
```

## `server`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_SERVER__BIND` | `0.0.0.0:8080` | API and console |
| `KUBEN_SERVER__METRICS_BIND` | `0.0.0.0:9090` | Prometheus `/metrics` |
| `KUBEN_SERVER__ACTIVATOR_BIND` | `0.0.0.0:8081` | reserved for the scale-to-zero activator |
| `KUBEN_SERVER__PUBLIC_URL` | unset | the URL users open; used for absolute links |
| `KUBEN_ROLES` | `all` | roles of this process: `all`, `api`, `controller`, `activator` (comma-separated) |
| `KUBEN_SERVER__REQUEST_TIMEOUT_SECS` | `30` | per-request timeout (streams excepted) |
| `KUBEN_SERVER__MAX_BODY_BYTES` | `1048576` | request body limit (1 MiB) |
| `KUBEN_SERVER__STATE_DIR` | see below | files of this installation: the setup token, a generated admin password, the secret keyring and backups by default |

`KUBEN_ROLES` (or `kuben serve --roles`) overrides `server.roles` (`KUBEN_SERVER__ROLES`, a list: `["api", "controller"]`).

Without `state_dir`: `/data` when it exists (the container image and the chart), else systemd's `$STATE_DIRECTORY`, `$XDG_STATE_HOME/kuben`, `~/.local/state/kuben`, or the working directory.

## `database`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_DATABASE__URL` | none, required | a `postgres://` or `postgresql://` URL, e.g. `postgres://user:pass@host/db` |
| `KUBEN_DATABASE__MAX_CONNECTIONS` | `4` | pool size |

Kuben keeps its data in PostgreSQL. There is no default URL: without one the server stops with a message that shows how to run a local PostgreSQL:

```bash
docker run -d --name kuben-postgres -e POSTGRES_PASSWORD=kuben -p 5432:5432 postgres:17-alpine
export KUBEN_DATABASE__URL=postgres://postgres:kuben@localhost:5432/postgres
```

SQLite URLs are rejected, and the data of a 1.x install that used SQLite is not carried over.

The container image sets no database; the Helm chart sets `KUBEN_DATABASE__URL`, to its own PostgreSQL or to `database.url`. `kuben setup` writes the URL in the example above: the server's own PostgreSQL over its Unix socket, with peer authentication and no password. Connect as an ordinary role: `kuben doctor` warns (`database role`) when the role is a superuser or has `BYPASSRLS`, because row-level security is then bypassed.

## `kube`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_KUBE__KUBECONFIG` | unset | path to a kubeconfig; otherwise `$KUBECONFIG`, then `~/.kube/config`, then the pod's service account |
| `KUBEN_KUBE__CONTEXT` | unset | kubeconfig context to use |
| `KUBEN_KUBE__WATCH_NAMESPACE` | unset (all) | restrict informers to one namespace |
| `KUBEN_KUBE__REQUIRED` | `false` (`true` in the chart) | fail to start when no cluster is reachable |
| `KUBEN_KUBE__NAMESPACE` | the pod's namespace | home of the controller Lease and of `kuben-initial-admin` |
| `KUBEN_KUBE__LEADER_ELECTION` | `false` (`true` in the chart) | run the controllers only on the Lease holder; required when several processes have the controller role |

## `security`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_SECURITY__COOKIE_SECURE` | `auto` | `Secure` + `__Host-` on the session cookie. `auto`: only when `KUBEN_SERVER__PUBLIC_URL` is `https://`, so a plain-http install signs in and turns `Secure` once a TLS address is set. `true` behind a TLS proxy without a public URL (the chart's default); `false` only for development |
| `KUBEN_SECURITY__SESSION_TTL_HOURS` | `12` | session lifetime |
| `KUBEN_SECURITY__SESSION_CACHE_TTL_SECS` | `5` | upper bound for a revoked session to stay valid on another replica |
| `KUBEN_SECURITY__PASSWORD_MIN_LENGTH` | `12` | |
| `KUBEN_SECURITY__ARGON2_M_KIB` | `19456` | Argon2id memory per password hash, KiB (19 MiB) |
| `KUBEN_SECURITY__ARGON2_T` | `2` | Argon2id iterations |
| `KUBEN_SECURITY__ARGON2_P` | `1` | Argon2id parallelism |
| `KUBEN_SECURITY__LOGIN_CONCURRENCY` | `2` | concurrent Argon2id verifications; bounds memory under a login flood |
| `KUBEN_SECURITY__LOGIN_MAX_FAILURES` | `5` | per email + client IP, within the window |
| `KUBEN_SECURITY__LOGIN_MAX_FAILURES_PER_IP` | `30` | |
| `KUBEN_SECURITY__LOGIN_MAX_FAILURES_PER_ACCOUNT` | `100` | |
| `KUBEN_SECURITY__LOGIN_WINDOW_SECS` | `900` | 15 minutes |
| `KUBEN_SECURITY__TRUST_FORWARDED_FOR` | `false` (`true` in the chart) | use the last `X-Forwarded-For` hop as the client address, and `X-Forwarded-Proto` for whether the request came over HTTPS. Only behind a proxy that sets them |
| `KUBEN_SECURITY__TRUSTED_PROXIES` | empty | addresses or CIDRs (`10.42.0.0/16`) whose forwarded headers are believed; empty: every peer's, once `trust_forwarded_for` is on. `kuben setup` sets the pod network when the console sits behind Kuben's Gateway |
| `KUBEN_SECURITY__INSECURE_SETUP` | `false` | let `/setup` take the first admin's password over plain HTTP from another machine. Otherwise only HTTPS (directly or through a trusted proxy) or a loopback client (an SSH tunnel) may; the page says how |

See [Sign-in and throttling](/docs/guides/sign-in-security/).

## `telemetry`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_TELEMETRY__LOG_FORMAT` | `json` | `json` or `pretty` |
| `KUBEN_TELEMETRY__LOG_LEVEL` | `info` | `trace`, `debug`, `info`, `warn` or `error`; `RUST_LOG` wins when set. A 1.x filter such as `info,kuben_platform=debug` is still accepted, but only its global level counts |
| `KUBEN_TELEMETRY__OTLP_ENDPOINT` | unset | accepted, not used: no traces are exported yet (the support bundle leaves it out) |

## `runtime`

The 1.x server ran on Tokio, and these keys sized its thread pools. Since 2.0 the server is written in Go: the keys are still accepted, so an existing configuration keeps loading, but they have **no effect**.

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_RUNTIME__WORKER_THREADS` | unset | no effect since 2.0 |
| `KUBEN_RUNTIME__MAX_BLOCKING_THREADS` | `16` | no effect since 2.0 |
| `KUBEN_RUNTIME__BULKHEAD` | `false` | no effect since 2.0 (ADR-013: there is no second runtime) |

The Go runtime's own variables take their place. `GOMAXPROCS` (the threads running Go code at once) defaults to the CPUs available, and follows the container's CPU limit. `GOMEMLIMIT` (a soft memory limit, e.g. `GOMEMLIMIT=400MiB`) is unset by default; set it a little below the container's memory limit so the garbage collector works harder before the kernel kills the process.

## `bootstrap`

Used on the first start with an empty database. Outside a cluster, when no `ADMIN_PASSWORD` is set, nothing is seeded: the console shows `/setup`, where the first admin account is created (see [`kuben setup-token`](/docs/reference/cli/#setup-token)).

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_BOOTSTRAP__ORG_SLUG` | `default` | |
| `KUBEN_BOOTSTRAP__ORG_NAME` | `Default` | the name the `/setup` page asks for wins over this |
| `KUBEN_BOOTSTRAP__ADMIN_EMAIL` | `admin@kuben.local` | for a configured or generated password; `/setup` asks for the email |
| `KUBEN_BOOTSTRAP__ADMIN_PASSWORD` | unset | set: the admin is created with it. Unset in Kubernetes: a generated password goes into the Secret `kuben-initial-admin`. Unset outside: the `/setup` page. Never logged |

## `quota`

These limits apply to every organization of the installation. Only the operator sets them, and unset means unlimited. A deployment that would exceed a limit is refused when Kuben accepts it.

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_QUOTA__ORG_CPU` | unset | CPU requests of all apps at their peak, e.g. `32` |
| `KUBEN_QUOTA__ORG_MEMORY` | unset | memory requests of all apps at their peak, e.g. `64Gi` |
| `KUBEN_QUOTA__ORG_PODS` | unset | pods of all apps at their peak |
| `KUBEN_QUOTA__ORG_APPS` | unset | live apps |
| `KUBEN_QUOTA__ORG_ENVIRONMENTS` | unset | live environments |

## `backup`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_BACKUP__DIR` | `backups` in the state directory | where `kuben backup` writes |
| `KUBEN_BACKUP__KEEP` | `7` | how many backups are kept |
| `KUBEN_BACKUP__MAX_AGE_HOURS` | `26` | the server reports itself degraded and opens an incident when the newest good backup is older than this; `0` turns the check off |
| `KUBEN_BACKUP__BEFORE_UPGRADE` | `true` | take a backup before a new version migrates the database |

## `agent`

AgentLink, where cluster agents connect to Kuben (ADR-027).

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_AGENT__BIND` | unset (set in the chart) | where Kuben listens for agents (`host:port`); unset, it does not |
| `KUBEN_AGENT__HUB_NAME` | `hub.kuben.internal` | the name Kuben's certificate carries; agents check it |
| `KUBEN_AGENT__CERTIFICATE_HOURS` | `24` | lifetime of the client certificates Kuben issues to agents |
| `KUBEN_AGENT__HEARTBEAT_SECS` | `10` | how often agents send a heartbeat |
| `KUBEN_AGENT__LOCAL` | `false` (`true` in the chart) | enroll an agent in Kuben's own cluster |
| `KUBEN_AGENT__ADVERTISE` | unset | the address agents in the cluster dial (`host:port`) |
| `KUBEN_AGENT__NAMESPACE` | Kuben's own, else `kuben-system` | namespace of the local agent and its Secrets |

## `git`

The GitHub App Kuben acts as. Git sources are on only when the App id, its key file and the webhook secret are all set.

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_GIT__GITHUB_APP_ID` | unset | the App's numeric id |
| `KUBEN_GIT__GITHUB_PRIVATE_KEY_FILE` | unset | PEM file of the App's private key (PKCS#1 or PKCS#8 RSA) |
| `KUBEN_GIT__GITHUB_WEBHOOK_SECRET` | unset | the secret GitHub signs webhook deliveries with |
| `KUBEN_GIT__GITHUB_API_URL` | `https://api.github.com` | the REST API root, for GitHub Enterprise Server |
| `KUBEN_GIT__GITHUB_CLONE_URL` | `https://github.com` | where build pods clone from |

| `KUBEN_BUILD__RAILPACK_FRONTEND` | unset | Railpack's BuildKit frontend image; with `railpack_image`, enables Railpack builds |
| `KUBEN_BUILD__RAILPACK_IMAGE` | unset | the image with `sh` and the `railpack` CLI; unset, only Dockerfile builds run |
| `KUBEN_BUILD__CPU_REQUEST` | `500m` | |

## `ci`

External CI trust: a GitHub Actions workflow exchanges its OIDC token for a short-lived Kuben token under an organization's trust policy.

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_CI__GITHUB_ACTIONS` | `false` | accept GitHub Actions OIDC tokens |
| `KUBEN_CI__GITHUB_OIDC_ISSUER` | `https://token.actions.githubusercontent.com` | the only issuer trusted; its keys are read from `<issuer>/.well-known/jwks` |
| `KUBEN_CI__GITHUB_OIDC_AUDIENCE` | `server.public_url` | the audience workflows request |

## `secrets`

| Variable | Default | Purpose |
|---|---|---|
| `KUBEN_SECRETS__KEYRING_FILE` | `secrets.keyring` in the state directory, created with one key when missing | the keyring of key-encryption keys; every replica must read the same file, and it must be backed up apart from the database. See [Backup and restore](/docs/operations/backup-restore/) |

<Aside type="note" title="Platform settings live in the cluster">
`baseDomain`, `gateway`, `clusterIssuer`, `wildcardTlsSecret`, the registry and the size presets are **not** process configuration: they are the `KubenConfig` custom resource, so every replica and every `kubectl` user sees the same values. The Helm chart writes it from `platform.*`. See [Custom resources](/docs/reference/custom-resources/).
</Aside>
