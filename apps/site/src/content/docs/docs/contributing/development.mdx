## Toolchain

- **Rust** stable, MSRV 1.94 (`rust-toolchain.toml` pins it)
- **Bun** 1.4 or later: package manager, JS runtime and test runner. Node is not needed.
- **Turborepo** runs every task in both languages from one graph (installed by `bun install`).
- **kind** for the end-to-end tests, **Helm** for the chart.

<Steps>

1. Clone and set up. `setup` installs the Rust toolchain components, the JS dependencies and cargo-nextest.

   ```bash
   git clone https://github.com/Teamtem-dev/kuben.git
   cd kuben
   bun run setup
   ```

2. Start a PostgreSQL. Kuben keeps its data only there, in dev mode too, and has no default database:

   ```bash
   docker run -d --name kuben-postgres -e POSTGRES_PASSWORD=kuben -p 5432:5432 postgres:17-alpine
   export KUBEN_DATABASE__URL=postgres://postgres:kuben@localhost:5432/postgres
   ```

3. Run the API and the console. The API listens on `:8080` in dev mode (pretty debug logs, insecure cookie) and uses the database in `KUBEN_DATABASE__URL`; Vite serves the console on `:5173` and proxies `/api` to it.

   ```bash
   bun run dev
   ```

   The first start opens the setup page, where you create the admin account (no token is needed on `localhost`).

4. Before pushing, run what CI runs: rustfmt, clippy with `-D warnings`, tests, doctests, the TypeScript checks, Biome, the generated-file drift check and the web build with its size budget.

   ```bash
   bun run ci
   ```

5. If you touched controllers or the API, also run the end-to-end suite against a kind cluster:

   ```bash
   kind create cluster --config deploy/kind.yaml
   bun run e2e
   ```

</Steps>

## Everyday commands

| Command | Does |
|---|---|
| `bun run build` | debug builds of the Rust entrypoints and the web bundle |
| `bun run check` | `cargo check` and `tsc` |
| `bun run lint` | clippy (`-D warnings`, pedantic) and Biome |
| `bun run format` | rustfmt and Biome fixes |
| `bun run test` | cargo-nextest and `bun test`, plus doctests |
| `bun run gen` | regenerate `openapi.json`, `schema.d.ts` and the CRDs |
| `bun run drift` | regenerate and fail on any difference (what CI does) |
| `bun turbo run test --filter=kuben-store` | one package |
| `bun turbo run kuben#size` | release build with the embedded console, checked against the 30 MiB budget |

## The console

- **Tokens, not colours.** Pages use the semantic names in `apps/console/src/styles.css` (`bg-canvas`, `bg-surface`, `text-fg`, `text-muted`, `border-line`, `bg-accent`, `text-ok`, `text-warn`, `text-danger`, …). The dark and light themes are two blocks of values; a raw palette colour (`text-slate-400`) would look wrong in one of them.
- **Both directions.** Persian is right to left: use logical utilities (`ms-`, `pe-`, `start-`, `border-e`) and mark code, commands and addresses `dir="ltr"`. Interface text lives in `src/lib/messages.ts`; the Persian table has the English table's type, so a missing translation does not compile.
- **Components are written here.** The spike for M2.15 weighed shadcn and Base UI against small components of our own: the console needs few widgets, stays under its size budget, and keeps the strict content security policy (`script-src 'self'; style-src 'self'`, nothing inline) without an exception. A library comes in only for a widget that is hard to make accessible by hand (a combobox, a date picker), and only if it sets styles through the CSSOM, never inline markup. `src/lib/csp.test.ts` fails on inline scripts, style attributes or injected HTML.
- **Self-hosted fonts only.** Inter's Latin subsets ship in `src/assets/fonts` with their licence; nothing is loaded from another origin (`font-src 'self'`).

## Rules

- **Dependencies.** Rust versions live only in `[workspace.dependencies]`; JS versions only in the root `package.json` catalog (packages write `catalog:`). Every new crate must pass `cargo deny check`.
- **Generated files are committed.** After changing API types or CRDs, run `bun run gen` and commit `packages/api-client/openapi.json`, `packages/api-client/src/schema.d.ts` and `charts/kuben/crds/`. CI fails on drift.
- **Every handler has a unique `operation_id`** in `#[utoipa::path]`; the TypeScript types and the audit log are keyed by it.
- **CRD types stay structural:** no internally tagged enums; use one-of structs with optional fields (`Source { image, git }`). A test guards this.
- **Budgets are gates:** binary ≤ 45 MiB, image (Kuben and its agent) ≤ 50 MiB, console JS ≤ 200 kB and CSS ≤ 25 kB (brotli). Raising a budget needs a written reason in the pull request.
- **Commits** follow Conventional Commits (`feat(api): …`, `fix(controller): …`). Label pull requests (`feature`, `bug`, `security`, `breaking`); release notes are grouped by label.
- **Migrations are PostgreSQL only** (ADR-025), in `crates/kuben-store/migrations/postgres/`.

## The review checklist

`CONTRIBUTING.md` lists 18 invariants, each closing a class of bug found in the system Kuben replaces: opaque sessions and no JWT in the browser, Argon2id only, no injection through user strings, no global mutable cluster context, informers instead of polling, readiness only after sync, embedded migrations under a lock, one source of truth per datum, server-side apply with conditions, and more. Reviewers check the ones a change touches. Read it before opening a pull request.

Please use [private vulnerability reporting](https://github.com/Teamtem-dev/kuben/security/policy), not a public issue.
</Aside>
